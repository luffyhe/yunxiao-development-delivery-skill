# 隔离环境快速推进模式

## 1. 目的

快速推进模式用于生命周期冒烟、示例项目和其他明确隔离的验证环境。它跳过“等待非作者评审”和“作者自审批”步骤，让已经验证并推送的不可变提交继续进入测试部署；不修改 Codeup 保护规则，也不把未合并代码冒充成已合并。

## 2. 启用条件

必须同时满足：

1. 用户在当前任务中明确要求快速推进或明确要求跳过 MR 作者审批验证；
2. Codeup 返回仓库为示例仓库，或项目、流水线和部署目标均有证据证明是隔离冒烟环境；
3. 需求、代码和发布边界明确禁止触达真实生产；
4. 开发侧最终验证通过，远端源分支 HEAD 与本地提交完全一致；
5. MR 已创建并关联当前需求/开发任务，目标分支正确且无代码冲突；
6. 已直接尝试一次平台允许的合并，唯一拒绝原因是缺少非作者评审或作者禁止自审批。

任一条件不满足时使用普通模式。真实业务仓库、生产发布、权限不清、代码冲突、错误目标分支、推送失败、MR 技术不可合并或其他平台拒绝均不得使用本模式。

## 3. 固定动作

1. 不调用 `codeup-review-change-request`，不添加自己为评审人，不等待他人审批。
2. 保留开放 MR，不关闭、不伪造合并状态、不强推、不关闭保护规则。
3. 生成 `oneos.rapid-delivery/v1` 证据，至少包含项目、仓库、需求、开发任务、MR、源分支、目标分支、远端提交、开发验证、合并尝试结果、拒绝原因和启用依据。
4. 把远端源分支的不可变提交作为 `deliveryRevision`。后续 test 流水线必须能够按该精确分支或提交运行，并证明部署制品包含它。
5. 实际完成时间使用该远端提交的可信提交时间并写入实际工时记录的工作描述；工作日期只取其自然日期，实际工时仍按 `codex-time-accounting.md` 统计，不得用自然时间代替。
6. 测试任务和交接必须明确 `mergeState=OPEN_REVIEW_SKIPPED`，不能写成“已合并”。
7. 若流水线只接受合并后的目标分支、无法指定源分支/提交，快速模式止于流水线门禁，不得触发不相关流水线补偿。

## 4. 回报

至少输出：

```text
模式：隔离环境快速推进
作者自审批：未执行
MR：开放，未合并
合并尝试：已执行一次；仅被评审门禁拒绝
交付版本：<远端源分支提交>
真实生产：未触发
后续流水线：必须部署上述精确版本
```
