# 批量实现本人开发任务与批量修复本人Bug

## 1. 触发入口

以下表达归一为同一个批量`/go`目标：

```text
/go 实现所有负责人是我的开发任务
/go 实现我的全部开发任务
/go 开发我负责的所有开发任务
```

可选范围：

```text
/go 实现所有负责人是我的开发任务 项目=统一运营管理平台PC端 迭代=V1.3
```

不带范围时查询当前登录云效账号在全部可访问、未归档项目中的开发任务。不得按显示名猜“我”，必须取得当前账号唯一ID。

## 2. 固定任务快照

开始时一次性形成快照，筛选：

- 负责人账号ID等于当前账号。
- 标题以`【开发】`开头。
- 状态为`待处理`或`处理中`。
- 未删除、未归档、未取消。

同一任务编号只保留一次。批次运行期间新分配的任务不加入本批，留到下次执行。

先展示：序号、项目、迭代、开发任务、关联需求、状态、从标题判定的类型、自动判定的范围、自动发现的目标项目/仓库、实际集成分支和预检结果。按项目、迭代、计划完成时间、优先级、任务编号稳定排序；缺少排序字段放到同组末尾。

## 3. 逐项调用单任务处理器

对每个任务构造并执行：

```text
/skill yunxiao-development-delivery
/go 开始开发:任务=<开发任务编号>
```

每条任务从可用关系、任务/父任务、需求材料和项目上下文判定新增/优化与范围，再从项目配置、Codeup、页面/API和代码事实自动发现前后端项目。前端优先`develop`、后端优先`dev`；名称不存在时使用仓库真实集成/默认分支。对话缺少仓库地址、工作项不是开发子任务、关系缺失或自动化规则不可用均不阻塞。

进入每条任务前记录`Codex任务ID + 开发任务ID + 分段开始检查点`，离开该任务时记录分段结束检查点和平台主动执行秒数。后续`完成开发`按`references/codex-time-accounting.md`把该分段计入对应开发任务。一个批量Codex任务内的整段时长不得复制给多个开发任务。

- `待处理`：执行完整单任务流程；首个子任务开工要求父交付=`已分配`，后续兄弟任务允许父交付=`处理中`。
- `处理中`：从最后一个可验证检查点续跑；缺首次开始、正式关系或自动化日志时补充可取得的证据并继续，不覆盖已有开始时间或重复创建分支。
- 需求已因同一交付下的其他开发任务进入`开发中`且父交付任务进入`处理中`时，允许新的`待处理`开发子任务开工，但必须验证兄弟任务及两级状态变化证据；只期待本任务`待处理→处理中`，不重复推动交付或需求状态。

每个任务都保留材料清晰度、代码、验证及新增需求Bug闭环门禁；工作项类型、关系、对话仓库地址、固定分支名和自动化规则状态按单任务新版规则不作为门禁。单任务`开始开发`通过后，结果中必须带下一阶段：

```text
/skill yunxiao-development-delivery
/go 完成开发:任务=<开发任务编号>
```

批量“实现”默认只完成`开始开发`节点，不代替每条任务的`完成开发`提交与直接合并节点。

## 4. 仓库隔离

每个任务在独立Git worktree或等价隔离工作区中实现，目录和分支绑定任务编号。不得在含另一任务未提交改动的工作区切换分支或混写代码。

若无法安全建立或复用隔离工作区，把该任务记为阻塞并继续。批量`/go`仍不授权提交、推送、创建MR、合并或部署，批次结束时保留每个任务的工作区路径以及带`/skill yunxiao-development-delivery`的`/go 完成开发`口令。

## 5. 失败隔离与继续

单任务遇到停止条件时：

1. 立即停止该任务的后续写操作。
2. 保留已经完成且验证过的安全步骤，不伪造回滚或成功。
3. 记录失败门禁、当前值、期望值、已完成步骤、未执行动作、影响和处理建议。
4. 继续快照中的下一个任务。

只有无法识别当前账号、无法取得任务列表、登录/权限阻断全部项目或执行环境整体不可用时，才停止整个批次。

## 6. 批次完成口径

“批次遍历完成”表示快照中的每个任务都已尝试，不表示全部实现成功。

```text
批次目标完成 = 快照任务数 > 0
且 每个任务均达到其单任务完成门禁
```

存在阻塞或未实现任务时，不把“实现所有任务”的`/go`目标标记为完成；输出完整清单，修复前置条件后使用：

```text
/go 继续实现我的开发任务
```

续跑只重试原批次未完成任务并重新读取真实状态；已完成任务按幂等成功跳过。用户重新执行“实现所有”时才建立包含新任务的新快照。

## 7. 汇总格式

```text
批次范围：
当前账号：
快照任务数：
实现完成：
处理中未闭环：
门禁阻塞：
逐项结果：
- <任务ID> <需求ID> <完成|未完成> <Codex分段/主动秒数> <工作区/分支> <原因或证据>
未实现任务及情况：
- <任务ID> 失败门禁=<...> 当前值=<...> 处理建议=<...>
下一条口令：
```

## 8. 批量修复本人Bug

标准入口及语义相同的入口：

```text
/skill yunxiao-development-delivery
/go 修复负责人是我的所有Bug
```

```text
/skill yunxiao-development-delivery
/go 修复我负责的全部Bug
```

```text
/skill yunxiao-development-delivery
/go 处理所有分配给我的Bug
```

开始时唯一解析当前账号ID，并冻结满足以下条件的Bug列表：

- 负责人账号ID等于当前账号。
- 当前状态在项目真实工作流中要求开发人员处理，例如待处理、处理中、重新打开或等价状态。
- 未删除、未归档、未取消、未关闭。
- 不是`已修复`、待复测或其他下一责任人为测试的状态。

先展示Bug编号、项目、迭代、当前状态、优先级、计划完成时间、影响范围和预检结果。关联需求、关联开发任务和仓库信息作为可选列：没有时显示`无`，不得把空值判为阻塞。按项目、迭代、优先级、计划完成时间和Bug编号稳定排序。运行期间新分配的Bug不加入本批。

对每个Bug调用同一个单Bug处理器：

```text
/skill yunxiao-development-delivery
修复bug:<BUG-ID>
```

每个Bug使用独立worktree或等价隔离工作区。单Bug处理器负责读取、复现、定位、修复、验证、提交、MR直接合并尝试、test部署证据和`已修复`交接；批量入口不复制或放宽代码冲突、目标分支、技术可合并性和平台保护规则。

某个Bug遇到复现材料、权限、目标代码库证据冲突、代码冲突、目标分支错误、MR技术不可合并、平台拒绝或环境阻塞时，停止该Bug，记录当前值、期望值、已完成步骤和修复建议，然后继续下一个Bug。评审、CI和讨论状态不读取、不等待、也不构成阻塞。Bug负责人变化、没有关联项或仓库信息均不属于阻塞，也不自动改派；单Bug处理器从工作区、Bug内容和运行证据定位代码库。只有当前账号无法识别、Bug列表无法取得、全局登录/权限失败或执行环境整体不可用时才停止整个批次。

批次完成口径：

```text
批次目标完成 = 快照Bug数 > 0
且 每个Bug均已具备test复测条件
且 每个Bug状态均为已修复
```

“列表遍历完成”不等于“全部Bug修复完成”。最终必须分别报告：

```text
批次范围：
当前账号：
快照Bug数：
已修复并交测试：
门禁阻塞：
仍需开发处理：
逐项结果：
- <BUG-ID> <需求ID> <已修复|未修复> <工作区/分支/MR> <证据或原因>
```
