# 云效浏览器执行提速与准确性

只在没有可靠专用API或连接器、需要通过云效网页执行时读取本文件。提速不得减少门禁、正式关系或保存结果的核验。

## 1. 复用稳定会话

1. 优先复用用户已登录的Chrome标签页和持久浏览器会话，不重复登录、重复打开首页或重新发现组织。
2. 在同一任务链内保留项目ID、工作项内部ID、编号和当前任务标签页；ID来自页面真实链接或语义DOM，不自行推导。
3. 页面跳转优先使用已验证的工作项编号入口或内部链接。遇到登录、验证码、OTP或授权确认时停止。

## 2. 一次完成写前取证

对`分配任务`先打开明确编号的`【交付】`任务，在一次语义DOM读取中尽量收齐：

- 组织、项目名称和项目ID；
- 交付任务编号、标题、状态、负责人和内部ID；
- 正式关联需求的编号、状态和内部ID；
- 迭代、模块标签及需要继承的标题信息；
- 已有开发子任务及其编号，防止重复创建；
- 产品交棒描述和系统编号是否冲突。

按`yunxiaopmapp-handoff.md`一次判定全部门禁。任一门禁失败时零写入；不要在多个页面间反复尝试修补前置数据。

## 3. 幂等后集中写入

1. 先按正式父子关系和编号确定“创建”或“复用”，不要按标题模糊查重。
2. 创建后立即记住开发任务编号和内部ID。
3. 在开发任务页面集中填写负责人、计划日期、预计工时、迭代、模块标签和托管的`## 下一阶段`区块，减少重复打开编辑器。
4. 创建并核验`TASK_SUB→【交付】`与`ASSOCIATED→需求`。选择工作项时使用精确编号与标题，不使用列表位置或屏幕坐标。
5. 下拉框、成员搜索和关联搜索是异步控件；等待可识别的精确选项出现后再选择，不把短暂空列表当成无结果。

## 4. 使用语义DOM而非截图猜测

- 优先读取可访问名称、文本、链接、表格行、工作项编号、状态按钮和字段值。
- 截图仅用于语义DOM无法表达的视觉状态或人工确认，不把OCR作为结构化字段的首选来源。
- 使用精确工作项编号、标题、人员名称和链接定位；不要依赖易漂移的CSS层级、像素坐标或某一行固定位置。
- 写入后以页面回读为准，不能用“点击过保存”推断保存成功。

## 5. 一次延迟回读

写入完成后等待5秒；若云效显示异步处理中，可在安全规范允许的5–30秒范围内延长。随后用一个聚合回读同时检查：

- 开发任务标题与状态；
- 父`【交付】`任务状态：分配后=`已分配`，首个子任务开始后=`处理中`，全部非取消子任务完成后=`已完成`；
- 负责人、计划开始、计划完成和预计工时；
- 迭代和模块标签；
- 父交付任务链接；
- 直接关联需求编号及需求状态；
- `## 下一阶段`中的Skill选择器和下一条`/go`命令。

所有检查均通过才返回成功。仅对失败项做定向复查；不要为了确认一个字段重新走完整流程。父任务链接和需求关联已在开发任务页稳定回读时，无需再次打开父任务；存在冲突或缺失时才回源核验。

## 6. 准确性优先级

执行顺序固定为：

```text
精确编号定位
→ 一次写前取证与门禁
→ 幂等创建或复用
→ 集中填写
→ 等待异步保存
→ 一次聚合回读
→ 仅复查失败项
```

不得通过跳过门禁、省略关系、缩短异步等待、忽略字段回读或相信旧页面缓存来提速。
