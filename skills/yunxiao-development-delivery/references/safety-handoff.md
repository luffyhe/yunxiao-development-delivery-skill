# 安全实施与跨角色交接

## 写入前

1. 明确组织、项目、项目ID、工作项类型、工作项编号和流程模型。
2. 把项目和迭代显示名解析为唯一ID；零个或多个匹配均停止。
3. 区分读取、规划和写入授权。文档、审计和“为什么”不授权修改。
4. 复用已登录会话或获批连接器，不记录账号、密码、Cookie、Token、OTP、Webhook密钥或私钥。
5. 备份相关规则的触发、条件、动作、顺序、启用状态和执行账号。
6. 对`/go 开始开发`，根据需求、任务、项目配置、可访问Codeup仓库、页面/API、代码关系和当前工作区自动确定目标项目；不要求当前对话提供仓库地址。证据冲突且无法安全确定修改对象时才停止。
7. 对`修复bug:<BUG-ID>`，验证Bug状态需要开发处理、复现输入和目标环境足够。负责人、关联项和仓库信息均不构成门禁；不自动改派。命令只授权该Bug及其证据定位代码库的修复和测试集成提交，不授权生产部署。
8. 对`/go 完成开发`，先确认可读取Codex任务主动执行时长和云效`实际完成时间`、`实际开发工时`字段。只有自然时间跨度、无法分段的混合任务或字段单位/精度不明时，不得填写或完成任务。

## 线上修改

- 一次只改一个明确对象，保存后重新打开核验。
- 每个自动流转必须检查预期当前状态。开发Skill只拥有交付任务的`待处理→已分配→处理中→已完成`状态路径，不得改派交付负责人或覆盖其计划与工时。
- 创建开发任务时仍使用标题前缀和正式关系增强追溯；显式开始/完成开发命令不以工作项类型、标题前缀或关系缺失作为门禁。
- 标签仅表示业务模块。
- 原生规则不能读取关联任务标题或不能更新关联需求时，使用`integration_bridge`、`manual`或`not_supported`，不得伪装为原生自动化。
- 新规则不补触发历史事件；历史修复单独记录。
- 手工准备状态不能作为自动化通过证据。

## 验证与结果

每次写入后等待5–30秒，检查状态、正式关系、执行日志和后继规则。结果只使用：

- `通过`
- `异步通过`
- `未触发`
- `误触发`
- `阻塞`

任何节点门禁失败时必须“零写入并解释”，至少返回失败检查项、真实值、期望值、未执行动作和修复建议。不得在失败分支中自动修正前置状态或关系后继续。

至少执行一个负向场景：错误源状态、错误标题前缀、重复事件、部分资产完成或错误环境。开发任务缺正式关系仍是负向场景；单Bug无关联项或无仓库信息不是负向场景。

## 交接协议

交接给另一个Skill时输出：

```text
来源Skill：
目标Skill：
项目名称/ID：
迭代名称/ID：
需求编号/当前状态：
正式关联任务：
代码/测试/发布资产：
已验证证据：
未完成项：
幂等键或事件ID：
允许的下一动作：
建议下一口令：
```

接收方必须重新读取真实状态，不能只相信交接文字。已满足的动作按幂等成功处理，缺失或冲突时停止。

所有建议下一口令必须显式包含：

```text
/skill <目标Skill名称>
```

### YunxiaoPMapp接入最小契约

```text
来源Skill：YunxiaoPMapp
需求编号/当前状态：<REQ-ID> / 待开发
正式关联任务：【交付】<DELIVERY-ID> / 负责人何斐 / ASSOCIATED→需求
未完成项：交付描述占位风险（若有）
允许的下一动作：开发Skill执行“分配任务”，创建或复用【开发】子任务
```

YunxiaoPMapp明确不创建`【开发】`/`【测试】`。接收方不得把两者缺失判为产品交棒失败，也不得补建产品阶段的交付、分析或设计任务。分配开发时不得把交付任务本身改派给开发人员。

## 状态所有权

| 范围 | 所有者 |
|---|---|
| 待处理至待开发、范围变更、产品验收关闭 | `YunxiaoPMapp` |
| 待开发至待测试、交付任务已分配/处理中/已完成、代码资产、缺陷修复、直接合并尝试、测试任务准备 | `yunxiao-development-delivery` |
| 待测试/测试中至测试完成、用例与缺陷复测 | `yunxiao-test-management` |
| 测试部署证据、发布中、发布完成/失败 | `yunxiao-release-operations` |

产品阶段到`待开发`的状态变化只由`YunxiaoPMapp`负责；开发Skill不得补偿或替代。开发Skill从已验收的待开发交棒开始，拥有交付任务`待处理→已分配→处理中→已完成`以及后续开发真实执行和完成结论。完成开发时先为每个开发任务回读实际完成时间和Codex换算后的实际开发工时；全部非取消开发子任务完成后再确认交付=`已完成`、需求=`开发完成`，并创建/复用测试任务；唯一测试主管存在时指派，否则保留原负责人或留空并报告，不阻塞需求`开发完成→待测试`。

`/go 完成开发`在MR创建后不检查或等待评审、CI和讨论状态，直接尝试合并到已核验的真实集成分支。允许自动批准自己的MR。代码冲突、错误目标分支、技术上不可合并或Codeup按当前权限/保护设置拒绝时停止并回报原始原因；不得强推、使用管理员绕过或关闭保护规则。

## 停止条件

遇到验证码、OTP、登录批准、权限提升、保护分支歧义、同名项目/迭代/流水线无法区分、生产范围不清或证据不一致时停止并请求最少必要信息。

## 回滚

先禁用本次新增规则或桥接入口，再恢复修改前配置。保留任务、关系、执行日志和发布证据；删除规则、任务、分支、MR、流水线或测试资产需要单独授权。
