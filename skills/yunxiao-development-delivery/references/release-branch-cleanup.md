# 发版任务分支清理

## 命令与边界

```text
/skill yunxiao-development-delivery
清理分支：发版任务=TASK-900
```

这是独立、按需执行的开发命令。发布Skill不发信号、不等待结果，也不拥有本流程。

命令仅授权：

1. 读取一个精确发版任务及其生产证据。
2. 发现该发版范围内的开发、Bug、hotfix和release分支。
3. 删除逐条通过门禁的精确Codeup远程分支。
4. 在当前命令运行机器上，安全删除能访问且通过本地门禁的对应本地分支。

不创建云效任务、评论、待办、通知或自动化规则，不修改发版任务、需求、开发任务或Bug状态，不运行流水线，不删除Tag，不操作其他开发人员电脑。

## 处理顺序

### 1. 唯一定位发版

按发版任务ID读取：

- 组织、项目、迭代和发版任务真实状态
- 本批需求
- prod流水线、精确执行ID、环境和终态
- 生产Tag、Commit或可追溯到Commit的不可变制品摘要
- 发布范围与生产版本的对应证据

发版任务不是`发布完成`、prod执行未成功、正在回滚/待回滚、范围冲突或缺少不可变生产版本锚点时，命令整体停止且零删除。

### 2. 发现候选

优先从可信关系发现：

1. 发版任务正式关联的本批需求。
2. 需求对应的开发任务和已关闭Bug。
3. 这些工作项正式关联的MR和源分支。
4. MR的仓库ID、源分支、目标分支、合并方式、合并Commit和当前远程HEAD。

按`仓库ID + 精确分支名`去重。同一工作项跨多个仓库、一个工作项多个分支、多个仓库中存在同名分支时，全部独立判定。

分支名、提交说明或MR标题中的工作项编号只用于发现候选，不能单独证明可删除。缺少可信关系或MR证据的候选进入`人工复核`，不删除。

### 3. 逐分支门禁

每个远程候选必须同时满足：

1. 属于该发版任务的精确需求范围。
2. MR已合并到项目核验过的真实集成分支。
3. 没有来自该分支的开放MR。
4. 分支在MR合并后没有新增提交，删除前远程HEAD与已验证HEAD一致。
5. 变更已进入本次生产Tag、Commit或不可变制品；仅进入`dev/develop`不够。
6. 对应开发任务已完成。
7. Bug分支对应Bug已由测试关闭、未再次打开，且测试不再依赖该分支。
8. 没有处理中、待验证、重新打开或仍依赖该分支的工作项。
9. 分支不是默认、保护、集成或长期维护分支；`main`、`master`、`develop`和`dev`永不删除。
10. `hotfix/*`已回灌全部适用集成分支。
11. 项目保留期已满足；项目规则更严格时使用更严格规则。
12. 删除通道能在操作前后读取远程HEAD、MR状态和保护规则。

默认保留期（项目未配置时）：

| 分支 | 默认保留期 |
|---|---:|
| `feature/*`、`fix/*`、`bugfix/*` | 7天 |
| `hotfix/*`、`release/*` | 30天 |
| 默认、保护、集成和长期维护分支 | 永久保留 |

普通Merge用MR合并Commit和生产包含关系核验。Squash/Rebase使用Codeup的MR合并记录、变更集和生产Commit核验，不能只检查Git祖先。Cherry-pick或部分发布必须证明该分支实际变更已进入生产制品；不能证明就保留。

### 4. 删除远程分支

1. 删除前重新读取远程HEAD、MR、保护规则和生产包含证据。
2. 只删除单条已通过门禁的精确远程分支，不使用通配符或批量模糊匹配。
3. 不强推、不使用管理员绕过、不关闭保护规则。
4. 删除后重新读取；分支不存在才记`已删除`。
5. 删除前已经不存在时记`已不存在`，按幂等成功处理。
6. 单条删除失败时记录原始错误并继续下一候选，不升级风险重试。

### 5. 清理当前机器本地分支

只有当前机器存在对应仓库时才尝试：

1. 先执行`git fetch --prune`。
2. 工作区必须干净，且该分支不是当前检出分支。
3. 分支不能被任一`git worktree`检出。
4. 本地分支不得包含未推送或无法证明已合并的独有提交。
5. 上游关系必须明确，且对应精确远程候选已通过门禁。
6. 只使用安全删除`git branch -d <精确分支名>`，永不使用`-D`。

脏工作区、独有提交、上游不明、worktree占用或安全删除被Git拒绝时保留并说明原因。不得清理开始命令前就存在的用户未提交改动。

其他开发人员电脑上的本地分支无法由当前命令远程删除。结果中列出：

```text
其他开发机待处理：请在对应开发机执行同一条“清理分支：发版任务=ID”命令
```

远程分支已不存在不影响该命令在另一台开发机继续完成本地清理。

## 幂等与失败

- 同一发版任务可重复执行；已删除/已不存在分支不报错。
- 一条分支门禁失败只保留该分支，不阻塞其他候选。
- 发版级门禁失败时全部零删除。
- 清理失败或部分保留不修改发布结果和任何工作项状态。
- 线下交流、口头确认和分支名称不能替代生产、MR、工作项和远程HEAD证据。
